# PaliaAPK HUB update alerts and FCM push notifications

The Android client registers an FCM token, saves it to Supabase, checks the published catalog on launch/resume, and handles notification taps by opening the relevant `app.html?id=...` page.

## One-time setup required

The code changes alone cannot send real push notifications until the Supabase function and database webhook are configured.

### 1. Deploy the SQL migration

Run `supabase/migrations/202610100001_device_push_tokens.sql` in the Supabase SQL Editor for project `ralinnuegsbuvlhwpzln`.

### 2. Create a Firebase service-account key

In Firebase Console for project `shanpalia-apk-hub`, open **Project settings → Service accounts → Generate new private key**. Keep this JSON private. Do not commit it to GitHub and do not put it in the website or APK.

### 3. Deploy the Edge Function and set secrets

Deploy `supabase/functions/notify-published-app/index.ts` to the same Supabase project. Set these function secrets:
- `FCM_SERVICE_ACCOUNT_JSON`: the complete Firebase service-account JSON as a single JSON secret.
- `PUBLISH_WEBHOOK_SECRET`: a long random secret generated by you.
- `SUPABASE_URL`: `https://ralinnuegsbuvlhwpzln.supabase.co`.
- `SUPABASE_SERVICE_ROLE_KEY`: the project's service-role key. Store only as a server-side secret.

The function has JWT verification disabled because the database webhook authenticates with the separate `x-publish-secret` header. Keep that header secret private.

### 4. Add a Supabase Database Webhook

In Supabase **Database → Webhooks**, create an HTTP POST webhook on table `public.apps`, event **INSERT**, pointing to:

`https://ralinnuegsbuvlhwpzln.supabase.co/functions/v1/notify-published-app`

Add header `x-publish-secret` with the exact same value as `PUBLISH_WEBHOOK_SECRET`. Use JSON request body containing the database event record (the standard Supabase Database Webhook payload). The function ignores records unless `update_available` is boolean `true`.

The Admin Panel's **Publish** action now sets `update_available: true`; **Save Draft** sets it to `false`. Check that `public.apps.update_available` exists as a boolean column before publishing. If it does not, add it with:

```sql
alter table public.apps
add column if not exists update_available boolean not null default false;
```

### 5. Build and publish a new APK

Build from `shanpalia/PaliaAPK-HUB-Android` using the existing Codemagic workflow. Install the new signed APK, open it once, and allow notifications when Android asks. Android 13+ requires this permission. Existing installs will not receive push until they update to a build containing this client.

### Notes

- In-app catalog alerts work on app launch/resume and are not an instant background service.
- Push notifications are delivered by Firebase Cloud Messaging and can arrive while the app is closed, subject to Android notification permission and device battery/network settings.
- Tapping a push opens the corresponding public app details page.
- This implementation does not silently install APKs; users choose to open/download the update.
